Conversion of EER Model into Relational Model 
The Extended Entity-Relationship Model is a more complex and high-level model that extends 
an E-R diagram to include more types of abstraction, and to more clearly express constraints. 
All of the concepts contained within an E-R diagram are included in the EE-R model, along with 
additional concepts that cover more semantic information. These additional concepts include 
generalization, specialization, and aggregation. 
 
Generalization is a bottom-up approach in which two lower level entities combine to form a 
higher level entity. In generalization, the higher level entity can also combine with other lower 
level entity to make further higher level entity. 
 
 
 
 
Specialization is opposite to Generalization. It is a top-down approach in which one higher 
level entity can be broken down into two lower level entities. In specialization, some higher 
level entities may not have lower-level entity sets at all. 
 
 
Conversion process for Generalization/ Specialization into Relational Schema:

Theory Questions 
1. What are ER Diagrams? What is their significance in DBMS? 
An Entity-Relationship (ER) Diagram is a graphical representation of the structure of a 
database. It illustrates the entities (objects or things), attributes (properties), and 
relationships between entities. ER diagrams are used during the database design process 
to create a clear blueprint before implementing the database. 
Main Components of an ER Diagram: 
• 
Entity: A real-world object or concept (e.g., Student, Employee, Book).  
• 
Attribute: A characteristic of an entity (e.g., Student_ID, Name, Age).  
• 
Relationship: The association between two or more entities (e.g., A Student enrolls in a Course).  
Significance of ER Diagrams in DBMS 
              ER diagrams are important in a Database Management System (DBMS) because they: 
1. Provide a clear visual representation of the database structure.  
2. Help in database design by identifying entities, attributes, and relationships before 
implementation.  
3. Reduce data redundancy by organizing data efficiently.  
4. Improve communication between database designers, developers, and users through an easy-
to-understand model.  
5. Ensure data integrity by defining relationships and constraints clearly.  
6. Simplify database maintenance and future modifications.  
7. Serve as a blueprint for converting the conceptual design into relational database tables. 
 
2. Explain the conversion process from ER to Relational. 
The ER-to-Relational conversion is the process of transforming an Entity-Relationship 
(ER) Diagram into a Relational Database Schema (tables). During this process, entities, 
attributes, and relationships are converted into tables with appropriate keys and 
constraints. 
Steps in ER to Relational Conversion 
1. Convert Strong Entities into Tables  
o Create a separate table for each strong entity.  

Department of Computer Science & Engineering 
 
 
o Entity attributes become table columns.  
o The primary key of the entity becomes the table's primary key.  
2. Convert Weak Entities into Tables  
o Create a separate table for each weak entity.  
o Include the primary key of the owner entity as a foreign key.  
o The combined key forms the primary key of the weak entity table.  
3. Convert One-to-One (1:1) Relationships  
o Add the primary key of one entity as a foreign key in the other entity's table.  
o Place the foreign key in the table with total participation whenever possible.  
4. Convert One-to-Many (1:M) Relationships  
o Add the primary key of the "one" side entity as a foreign key in the "many" side entity's 
table.  
5. Convert Many-to-Many (M:N) Relationships  
o Create a separate table for the relationship.  
o Include the primary keys of both participating entities as foreign keys.  
o The combination of these keys forms the primary key of the relationship table.  
o Include any relationship attributes in this table.  
6. Convert Multivalued Attributes  
o Create a separate table for each multivalued attribute.  
o Include the primary key of the parent entity as a foreign key.  
7. Convert Composite Attributes  
o Replace each composite attribute with its individual simple attributes.  
o Store only the simple attributes in the table. 
 
3. Explain the need of EER diagrams 
Enhanced Entity-Relationship (EER) Diagrams are an extension of ER diagrams that provide 
additional features to model complex database systems. They include concepts such as 
specialization, generalization, inheritance, aggregation, and categories, making database 
design more expressive and flexible. 
Need of EER Diagrams 
1. Model Complex Databases  
o 
EER diagrams can represent complex real-world scenarios that cannot be modeled effectively 
using basic ER diagrams.

4. Explain in detail Generalization, specialization and Aggregation and how do we convert 
them into relational model 
1. Generalization 
Generalization is the process of combining two or more similar lower-level entities into a 
single higher-level entity called a superclass. The superclass contains the common attributes 
shared by all the lower-level entities. 
Features: 
• 
It is a bottom-up approach.  
• 
Reduces data redundancy by storing common attributes in one place.  
• 
The superclass represents the generalized form of all subclasses.  
Conversion into Relational Model 
• 
Create one table for the superclass containing the common attributes.  
• 
Create separate tables for each subclass containing their specific attributes.  
• 
The primary key of the superclass becomes the primary key as well as the foreign key in each 
subclass table.  
 
2. Specialization 
Specialization is the process of dividing a higher-level entity into two or more lower-level 
entities called subclasses based on specific characteristics. Each subclass inherits the 
attributes of the superclass and may have additional attributes. 

Department of Computer Science & Engineering 
 
 
Features: 
• 
It is a top-down approach.  
• 
Supports inheritance of attributes and relationships.  
• 
Represents more specific entities from a general entity.  
Conversion into Relational Model 
• 
Create one table for the superclass with all common attributes.  
• 
Create separate tables for each subclass with their unique attributes.  
• 
The primary key of the superclass is used as the primary key and foreign key in each subclass table.  
 
3. Aggregation 
Aggregation is a process in which a relationship between entities is treated as a higher-level 
entity. It is used when a relationship itself participates in another relationship. 
Features: 
• 
Represents a relationship as an entity.  
• 
Helps model complex real-world situations.  
• 
Simplifies the representation of higher-level relationships.  
Conversion into Relational Model 
• 
Create tables for all participating entities.  
• 
Create a separate table for the aggregated relationship.  
• 
Include the primary keys of the participating entities as foreign keys in the aggregation table.  
• 
Add any attributes belonging to the aggregated relationship.

between a procedure and a function is, a function must always return a value, but a procedure 
may or may not return a value.

▪

A subprogram is a program unit/module that performs a particular task. These subprograms

subprogram can be invoked by another subprogram or program which is called the calling 
program.
